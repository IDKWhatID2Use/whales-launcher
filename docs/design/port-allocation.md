# 自动端口分配机制 —— 设计说明

> 目标：多实例同时运行时**自动避让端口**，既不抢占他人端口，也不因端口冲突而启动失败；
> 并发启动时不得选中同一端口；每个实例实际使用的端口必须可见、可查。

---

## 一、问题现状（改造前，全部来自代码与源码，非推测）

| 项 | 改造前的事实 |
|---|---|
| 端口从哪来 | **没有任何端口机制**。启动命令是 `node <dsh bin> --profile <名> [...appArgs]`，**不传 `--port`** |
| 因此落在哪个端口 | dsh 的硬编码兜底 **3080**：`dsh-web-app/cordis.patch.yml:139` → `port: !!js ctx.webStartup.port ?? 3080` |
| 冲突时的行为 | 进程以 `EADDRINUSE` 退出，`explainLaunchFailure` 提示用户「自己去启动参数里加 `--port 3081`」（`src/core/launch.ts`） |
| 用户唯一的出口 | 实例详情「启动参数」自由文本手写 `--port`（`src/renderer/views/detail/settings.ts`） |

也就是说：**同时启动 N 个实例，它们会全部抢 3080，只有一个能起来**。这正是本机制要消除的。

### dsh 侧的依据（决定了方案可行性）

```
dsh-web-app/lib/startup.js        --port <port>   "listen port; pass 0 to let the OS pick a free one"
dsh-web-app/cordis.patch.yml      webserver.port: ctx.webStartup.port ?? 3080
dsh-host-webserver/lib/index.js   webServer.port  → **绑定完成后**的真实端口（--port 0 时由内核给出）
dsh-web-app/cordis.patch.yml      web-runtime.printUrl: true（包内硬编码）
```

两条结论直接决定了设计：

1. **`--port 0` 是 dsh 原生支持的**，可以让内核分配一个必然空闲的端口 —— 端口耗尽时有兜底，绝不会"起不来"。
2. **真实端口一定会被打印出来**（`printUrl: true`），因此 `--port 0` 也能被如实记录 —— 这正是"记录实际端口"的落点。

## 二、设计决策（本机制的产品口径）

| 决策 | 取值 | 理由 |
|---|---|---|
| 分配策略 | **期望端口优先 + 占用自动避让 + 区间耗尽回落 `--port 0`** | URL 稳定可收藏；同时保证任何情况下都起得来 |
| 候选区间 | **3080–3179**（100 个） | 集中在 dsh 默认端口附近便于记忆，不碰常见服务端口 |
| 手写 `--port` 的语义 | **不算锁定**：被占用时仍自动避让，并明确提示「你指定的 N 被占，已改用 M」 | 用户选定的口径；保留"指定端口"的意图（作为期望端口），但不让它变成启动失败 |
| 记录形式 | 实例日志 + `runtime.port`（IPC/UI）+ 跨进程台账文件 | 三处互补：当场可见、界面可查、重启后仍在 |
| `instance.json` | **一个字节都不动** | 期望端口与实际端口全部落在台账里，因此不触发任何 schema 迁移风险 |

## 三、三层防护

三层各管一段，职责不重叠 —— 这是本设计最重要的结构决定。

### 第 1 层：进程内预留集（同步占位）

```ts
export function claimPort(port: number): boolean {
  if (reserved.has(port)) return false;
  reserved.add(port);        // 函数体内**没有 await**
  return true;
}
```

JS 是单线程的，因此"检查 + 占位"在这里是一个不可分割的原子步骤。
**这是需求 3（并发探测不得选同一端口）在进程内的强保证**，而不是"概率上不会撞"。

### 第 2 层：操作系统绑定探测（原子占用测试）

```ts
server.listen({ port, host: '127.0.0.1', exclusive: true })
```

用真实的 `listen` 而不是"连一下试试"：监听冲突由内核判定，不受防火墙、连接超时、
进程权限影响，也能同时看穿**另一个启动器进程**与**任何外部程序**的占用。

### 第 3 层：跨进程台账（`<root>/cache/ports.json`）

```jsonc
{
  "schemaVersion": 1,
  "allocations": {
    "<instanceId>": { "name": "实例名", "preferred": 3080, "last": 3081, "pid": 12345, "updatedAt": "…" }
  },
  "failures": { "3080": "2026-…" }   // 曾被 dsh 以 EADDRINUSE 拒过的端口（5 分钟 TTL）
}
```

台账负责**持久化期望端口**与**留审计记录**（需求 4），本身**不是互斥手段** ——
读改写做不到原子。互斥由第 1、2 层保证。这里刻意不夸大台账的作用。

**并发写必须串行**：台账是"读 → 改 → 写"的整文件替换。8 个实例同时启动时，
若并发执行，每个都读到同一份旧内容、各自写入自己那条，最后只剩 1 条 ——
"记录每个实例实际端口"就会静默地只满足 1/8。因此所有台账读写都走一条进程内串行链
（`withLedgerLock`），序列化粒度是整个分配过程。单个探测约几毫秒，代价可忽略。

## 四、接口

### 契约（`src/shared/contracts.ts`，唯一事实源）

```ts
export type PortSource = 'explicit' | 'ledger' | 'auto' | 'os';

export interface PortDecision {
  port: number;          // 交给 dsh 的 --port 值；0 = 交内核分配
  desired: number | null; // 期望端口（避让前想用的那个）
  avoided: boolean;       // 是否发生了避让
  source: PortSource;
  reason: string;         // 中文说明，直接进日志与界面
}

export interface InstanceRuntime {
  // …既有字段…
  port: number | null;   // 实际使用的监听端口
}
```

`InstanceRuntime.port` 是**唯一**新增的跨层字段：它经既有的 `onState` 广播直达渲染层，
因此**不需要新增任何 IPC 通道**，也不需要改 preload。

### 实现（`src/core/ports.ts`）

| 函数 | 职责 |
|---|---|
| `allocatePort(root, instance, explicitPort)` | 分配决策（唯一入口，内部持台账锁） |
| `releasePort(root, id)` | 进程退出时释放预留；保留 `preferred` |
| `forgetPort(root, id)` | 删除实例时清台账记录 |
| `notePortBound(root, id, pid)` | 启动成功后台账补 PID |
| `notePortFailure(root, port)` | 记录被 dsh 拒过的端口（自愈依据） |
| `isPortFree(port)` | 原子占用测试 |
| `claimPort` / `releaseClaim` / `reservedPorts` | 进程内预留集 |
| `scanOrder(start)` | 从期望端口开始的环形扫描序列 |
| `parseExplicitPort` / `withPortArg` / `hasMalformedPortFlag` | 参数解析与**原地改写** |

### 决策顺序

1. 用户显式 `--port N`（N ≠ 0）→ N 优先；
2. 台账里该实例的 `preferred`；
3. 区间内自动分配（**优先避开其它实例已认领的期望端口**与近期失败过的端口）。

期望端口被占用时按 `scanOrder` 向后避让；整个区间都不可用时回落 `--port 0`。
用户显式写 `--port 0` 时直接尊重，不进避让逻辑。

## 五、启动流程接线（`src/core/launch.ts`）

```ts
const requestedArgs = (req.appArgs ?? meta.launch.appArgs).filter(…);
const portDecision = (await hasWebSurface(root, meta))
  ? await allocatePort(root, { id: meta.id, name: meta.name }, parseExplicitPort(requestedArgs))
  : null;
const appArgs = portDecision === null ? requestedArgs : withPortArg(requestedArgs, portDecision.port);
const args = ['--profile', meta.profile.name, ...appArgs];
```

三个关键点：

### 1. 模板感知（否则会用一个新缺陷换掉旧缺陷）

`--port` **只有 Web 应用认**。传给 `headless` / `sdk` / `acp` 会被 commander 当作未知选项，
直接启动失败。因此 `hasWebSurface()` 决定是否注入，判据取 profile 的**实际组合包列表**
（`readBundles(readProfileManifest(...))` 是否含 `@deepseek-ai/dsh-web-app`），
而不是创建时的模板名 —— 用户后来通过插件管理启用/禁用了 Web 应用时也会跟着变。

清单**缺失或损坏**时一律回退到创建时的模板名。这里的"损坏"必须显式处理：
`fsx.readJson` 对文件缺失返回 `null`，但对 **JSON 语法错误是抛错** ——
不 catch 就会让整个启动在 spawn 之前断掉，把 dsh 自己的报错挡在外面，
用户只看到一句"JSON 解析失败"、日志里连启动行都没有。
（这个情形由独立审查的 trace 实测发现，已修为回退并补了回归测试。）
端口判断是**旁路信息**，任何时候都不该成为启动的阻断点。

### 2. 原地改写，而不是追加

`withPortArg` 把已有的 `--port` **改写值**，保证命令行里始终只有一个 `--port`。
追加会让语义依赖"后者覆盖前者"的解析细节，等于把正确性押在别人的实现上。

**形态非法的 `--port`（悬空、或值不是数字）一律不碰**：既不改写也不追加，交给 dsh 报出
它原本的使用错误。这样既不掩盖用户的笔误，也不会拼出 `--port --port 3080` 这种命令行。

### 3. 实际端口以 dsh 的输出为准

```ts
const actual = portFromUrl(url);   // 从 `http://127.0.0.1:<port>` 里取
notify(patchRuntime(meta.id, actual === null ? { url } : { url, port: actual }));
```

启动中先填入分配决策给出的端口，dsh 打印地址后再由**真实端口**覆盖。
`--port 0` 交内核分配时，这是唯一能知道端口号的地方。

### 4. 收尾

- 启动失败（Node 运行时不可用 / spawn 抛错 / PID 无效）→ 立刻 `releasePort`，
  否则本进程会一直占着它，后续实例会白避开一个"其实没人在用"的端口；
- 进程退出 → 释放预留（端口由系统回收），并保留 `preferred` 供下次复用；
- 退出码非 0 且 stderr 命中 `EADDRINUSE` → `notePortFailure` 记进台账，短时间内不再优先选用；
- 启动成功 → `notePortBound` 把 PID 写进台账。

## 六、记录形式（需求 4）

| 载体 | 内容 | 位置 |
|---|---|---|
| 实例日志 | `[whales] 端口：期望端口 3080 已被占用 → 自动避让到 3081` | `<实例>/logs/<时间戳>.log` |
| 界面 · 实例卡片 | 运行中的卡片多一个 `:3081` 统计项 | `src/renderer/views/instances.ts` |
| 界面 · 详情页 | 「监听端口」指标 | `src/renderer/views/detail.ts` |
| IPC | `InstanceRuntime.port` 经既有 `onState` 广播下发（**未新增通道**） | `src/main/runtime.ts` |
| 跨进程台账 | 每个实例的 `preferred` / `last` / `pid` | `<root>/cache/ports.json` |

**台账的 `last` 会以真实端口回填**：走 `--port 0`（内核分配）时，分配那一刻根本不知道端口号，
只有 dsh 打印出界面地址后才知道。因此 `notePortActual()` 在地址探测处把实际端口写回台账 ——
否则 `last` 会永远停在 0，"记录每个实例实际使用的端口"在兜底路径上就不成立。
（这一条是独立审查实测发现的：占满区间后启动，`runtime.port=53902` 正确而台账仍是 `last: 0`。）

文案示例：

- 自动分配成功 → `自动分配端口 3082`
- 期望端口被占 → `期望端口 3080 已被占用 → 自动避让到 3081`
- 手写端口被占 → `启动参数指定的端口 3080 已被占用 → 自动避让到 3081`
- 区间耗尽 → `候选区间已被占满 → 交操作系统分配空闲端口（--port 0），实际端口以启动输出为准`
- 显式 `--port 0` → `启动参数显式指定 --port 0 → 交操作系统分配空闲端口`

## 七、边界情况

| 情形 | 行为 |
|---|---|
| **可用端口耗尽** | 回落 `--port 0`，由内核分配 → **实例照常启动**，不会变成启动失败；真实端口从输出回填到 `runtime.port` **与台账 `last`** |
| **期望端口被显式锁定** | 本机制里**不存在**"锁定"语义：手写的 `--port` 只是"期望端口"，被占仍会避让并明确提示（用户选定的口径） |
| **用户显式 `--port 0`** | 直接尊重，不进避让逻辑；**仍写一条台账记录**（`last` 记 0，真实端口以启动输出为准），避免这类实例从审计里消失 |
| **实例退出后端口回收与重用** | 预留立即释放、系统随之回收；台账 `preferred` 保留 → 下次启动**优先复用同一端口** |
| **非 Web 模板** | 一个 `--port` 都不加，也不产生端口决策日志 |
| **用户写的 `--port` 形态非法** | 原样透传，不注入、不改写，由 dsh 报使用错误 |
| **手写端口超出 0–65535**（如 `--port 99999`） | 归入"形态非法"一类：**原样透传、不注入也不改写**，由 dsh 报出它自己的 schema 错误（dsh 是 `z.natural().max(65535)`）。本机制不擅自替用户改成一个他没写过的端口 |
| **`--port 03080` / `--port 65535`** | 前导零与边界值都是合法数字 → 视为显式端口并正常改写 |
| **`--PORT`（大小写不同）** | 本机制不识别（dsh 的 flag 是大小写敏感的 `--port`）→ 会另注入一个 `--port`；用户写错的 `--PORT` 仍会被 commander 报为未知选项，错误不被掩盖 |
| **`--port` 出现在 `--` 之后** | `--` 及其之后被视为**位置参数**：既不参与 flag 解析，也**原样搬运、绝不改写**（改写它等于改用户的数据，而不是配置）。改写只发生在 `--` 之前的 flag 区 |
| **台账损坏 / 手工改坏** | 降级为空台账继续（`readJson` 在文件损坏时**抛错**，因此这里显式 catch）；单条坏记录只丢弃该条 |
| **删除实例** | `forgetPort` 清掉台账记录，避免越积越多、也避免新实例白避开一个没人认领的端口 |
| **同一台机器开两个启动器** | 进程内预留集各自独立，但**操作系统绑定探测是共享的原子判定** → 不会撞端口 |

### 已知的残余窗口（诚实说明）

探测成功后我们会**关闭**探测 socket 再把端口交给 dsh，而 dsh 要到启动末期才真正绑定 ——
两者之间有**数百毫秒**的窗口（dsh 要组完整棵插件树）。该窗口内若被外部程序抢走，
dsh 会以 `EADDRINUSE` 退出。

处理方式是**自愈而非重试**：这次失败的端口会被写进台账的 `failures`，
5 分钟内任何实例都不再优先选用它 —— 下一次启动即自动避开，不会连续撞同一个坑。

**选择不实现"spawn 级自动重试"是刻意的**：那需要在最关键的启动路径上重构进程生命周期
（`active` 登记、日志写入器、`settled` 链、hooks 与返回值都要跨尝试复用），
其引入缺陷的风险高于它消除的那点窗口。若将来要做，正确的位置是把
"spawn → 等待绑定确认"抽成一个可重入的独立阶段，而不是在现有链上打补丁。

## 八、验收（实测结果）

判定刻意选用**外部可观测的事实**（真实 HTTP 请求、端口集合去重、台账逐条对账），
而不是启动器的自我报告。

### 单元与接线断言：`tests/core/ports.test.mjs`

**25 项，全绿。** 覆盖参数改写（两种形态 / 后者优先 / 非法形态不碰 / `--` 分隔符）、环形扫描序列、
原子占用测试、同步预留、自动分配、被占避让、显式 `--port 0`，
**8 路并发分配不重复且台账 8 条齐全**、**区间占满回落 `--port 0`**、
**实际端口回填台账**、释放后可重用、失败端口回避、删除实例清台账、坏台账降级、

### 独立对抗性审查（另一 agent，只读不改）

审查员用**自建探针**在真实 dsh 引擎上取证（`.spike/rev/`），报告 2 项 P1、2 项 P3，并明确区分了
"我验证过的"与"我只是推断的"。逐条处置：

| 审查发现 | 我的复核结论 | 处置 |
|---|---|---|
| **P1-1** 区间耗尽回落 `--port 0` 时台账 `last` 停在 0，需求 4 在兜底路径不成立 | **成立**。`runtime.port` 已是真实端口（53902），台账却没有 —— 同一时刻 `notePortBound` 拿到了 pid 却不回填端口 | 新增 `notePortActual()`，在地址探测处把真实端口写回台账；补单元测试 + **端到端测试**（`--port 0` 启动后台账应变 3999） |
| **P1-2** 命令行含 `--` 时注入导致实例起不来 | **部分成立，但根因不同**。它给的例子 `--no-open --port 4000 -- --port 4001` 报 `excessArguments`，是**用户自己写了两个位置参数**（`--` 之后 commander 一律当位置参数），我的改写只动了 `--` 之前的 flag，没有破坏它。**但它促我发现一个我确实造成的缺陷**：末尾悬空的 `--`（`['--no-open','--']`）原本 0 个位置参数、完全合法，我把 `--port N` 追加到它后面 → 凭空多出 2 个位置参数 → 把合法命令行弄坏了 | 注入改为**落在 `--` 之前**；`--` 之后原样搬运；补 3 条断言 |
| **P3** `--port -1` 的注释归因不准；`--PORT` 大写不识别 | 行为本身可接受（dsh 仍会报错），属注释精度问题 | 已在边界表里写准 |
| 注释声称 OS 探测"能看穿另一个启动器进程"是夸大 | **成立**。对*已占用*成立，但**不构成跨进程的分配互斥**：两个启动器进程同时探测同一个空闲端口会双双成功 | 重写 `ports.ts` 头部，单列「边界必须说清楚（刻意不夸大）」一节 |
| 台账跨进程并发写会互相覆盖 | **成立**，且我原本就在设计里声明"台账不是互斥手段" | 在设计说明里把"串行锁只在单进程内有效"写得更明确 |

审查同时确认了两项**已修复**项（profile 清单损坏挡住启动、启动抛错泄漏预留端口），
并明确"未发现永久残留泄漏""未发现假绿断言""契约兼容性未发现问题"。

### 验收过程中暴露并修掉的三个真实缺陷

这些都不是端口逻辑本身的缺陷，但**只有在"8 个实例真并发"这个场景下才会显形** ——
它们正是本机制要支持的使用方式，所以一并修掉：

| 缺陷 | 根因 | 修法 |
|---|---|---|
| `EBADF: bad file descriptor, close`（直接崩溃） | `proc.ts` 的 `spawnWithFiles` 里，`error` 与 `close` 事件**都会**调用收尾，收尾中的 `closeSync` 被调用两次；第二次关闭的 fd 号可能已被另一个并发 spawn 复用 → 关掉的是**别人**的捕获文件句柄 | 给收尾加幂等守卫（`proc.ts`） |
| `EPERM: operation not permitted, rename` | `fsx.ts` 的原子写只有 `removeDir` 有退避重试，`rename` 没有。8 路并发拉起 dsh 时磁盘压力最大的那一刻替换被拒（同工作区单纯的 8 路并发 rename 实测 320/320 成功，说明是压力相关的瞬时失败） | 给 `rename` 加同款退避重试，只对瞬时占用类错误重试（`fsx.ts`） |
| 台账并发丢记录 | 台账是"读-改-写"整文件替换，8 路并发时后写者覆盖前者，最后只剩 1 条 | `withLedgerLock` 进程内串行链（`ports.ts`，设计阶段即发现） |

另有一条**测试自身的缺陷**被修正：`tests/core/launch.test.mjs` 的既有断言写死了改造前的
argv 形状与运行时对象形状。修正时保留原测试意图（"启动器 flag 在最前"、"appArgs 追加在其后"），
而不是把它改成能过就行 —— 例如把 `deepEqual(args, ['--profile', p])` 改为
"前两位是 `--profile <p>` + 恰好一个区间内的 `--port` + 无多余参数"。
