# 02 · 五分钟上手

> 目标：从零到**一个正在运行的实例**。四步，每步都配图。

```
① 装引擎版本  →  ② 新建实例（向导四步）  →  ③ 启动  →  ④ 打开界面
```

---

## ① 装一个 dsh 引擎版本

左侧导航点 **版本管理**（或按 `Ctrl+2`）。

![版本管理](../assets/tutorial/17-engines.png)

*图 17：版本管理页。上半部分是「本地已安装」，下半部分是「可安装版本」（来源：npm registry 的 `@deepseek-ai/dsh`）。*

页面分成两段，**各自独立加载**：本地列表先出现，不被 npm 查询拖住；npm 列表有自己的加载/失败/超时态。

要装一个新版本：

1. 在「可安装版本」列表里找到目标版本（带 `预发布` 徽标的是 alpha 版本）；
2. 点该行右侧的 **安装**；
3. 下方控制台会**实时追加** npm 的安装输出 —— 首次安装要下载依赖，请保持网络畅通；
4. 装完后该版本会出现在上方「本地已安装」里，卡片上标着 `已安装`，并列出**哪些实例正在用它**。

卡片上还会显示体积（例如 `45.0 MB`）。**显示「未知」而不是 `0 B` 是有意的**：
引擎目录若经 junction 接入，统计不跟随链接，显示 `0 B` 会误导。

> **可以同时装多个版本。** 每个实例绑定单一版本，互不影响 —— 想试新版就再装一个，
> 旧实例继续跑旧版。

> ⚠️ **版本兼容提示**（页面顶部黄条）：dsh 不同大版本之间的 profile 格式不保证兼容。
> 把实例切换到更旧的版本前，请确认 profile 结构未被新版本改写。

## ② 新建实例（向导四步）

回到 **实例列表**，点右上角 **新建实例**（或按 `Ctrl+4`）。向导一共四步：

### 第 1 步：名称与外观

![向导第 1 步](../assets/tutorial/07-wizard-step1-name.png)

*图 7：向导第 1 步。左边填名称/图标/强调色/备注，右边实时显示**实例预览**与**配置摘要**。*

- **实例名称**（必填）：会作为 dsh profile 名校验 —— 不能包含 `/` `\` 等字符，
  也不能使用 `desktop`、`node_modules` 等保留名；
- **目录名由启动器自动派生并去重**，你不用操心重名；
- **图标 / 强调色**：强调色用于实例卡片的色条与头像背景；
- **备注**：写清「这个实例用来做什么」，实例多了以后非常有用。

右侧的**实例预览**和**配置摘要**会随输入实时更新，填错了当场就能看出来。

### 第 2 步：选择引擎版本

![向导第 2 步](../assets/tutorial/08-wizard-step2-engine.png)

*图 8：向导第 2 步。已安装的版本带绿色「已安装」徽标，未安装的带橙色「未安装」徽标。*

- 带 **已安装** 的版本可以**立即创建并启动**；
- 带 **未安装** 的版本也能选，但创建前需要下载安装（可在版本管理页看进度）；
- 一个实例只能绑定一个版本。**不同实例可以用不同版本。**

### 第 3 步：选择 profile 模板

![向导第 3 步](../assets/tutorial/09-wizard-step3-template.png)

*图 9：向导第 3 步。模板决定实例随附哪些组合包，创建后仍可继续装卸插件。*

| 模板 | 适合什么 |
|---|---|
| **Web 界面**（`web`） | 带本地 Web 界面，适合日常交互；**启动后自动探测界面地址** |
| **无界面批处理**（`headless`） | 一次性执行任务并输出最终结果，适合定时任务与脚本 |
| **SDK 服务**（`sdk`） | JSON-RPC stdio 服务，供其它程序嵌入调用 |
| **最小 SDK**（`sdk-minimal`） | 仅含最小运行时的 SDK 模式，启动最快、占用最低 |
| **ACP 服务**（`acp`） | ACP stdio 协议服务，对接编辑器与 IDE 插件 |

同一页还能指定 **profile 名称**（默认 `main`，对应 `$DSH_HOME/profiles/main`）。
已有实例使用另一个 profile 时，在这里填同名即可**复用那套配置**。

### 第 4 步：隔离策略

![向导第 4 步](../assets/tutorial/10-wizard-step4-isolation.png)

*图 10：向导第 4 步。四个维度各自选「独立 / 共享」，顶部还有三个快速预设。*

四个维度分别是**工作区**、**会话存档**、**设置文件**、**凭证**。第一次用建议直接点
**完全隔离（推荐）** 预设，四项全独立：

| 快速预设 | 效果 |
|---|---|
| **完全隔离（推荐）** | 四项全独立，互不干扰 |
| **存档互通** | 会话存档共享，其它独立 |
| **全部共享** | 能共享的都共享（谨慎使用） |

共享通过 **Windows junction** 实现 —— **不需要管理员权限**，也不需要开发者模式。

> 想深入了解共享的机制、风险与冲突处理，见 [06 隔离与共享](06-isolation-sharing.md)。
> 现在按推荐值走就行。

填完点 **创建实例**，向导会显示创建进度，完成后可以直接跳到新实例。

## ③ 启动实例

回到 **实例列表**，找到刚建的实例，点卡片上的 **启动**。

![运行中的实例](../assets/tutorial/15-running-detail.png)

*图 15：运行中的实例详情页。注意标题右侧的绿色「运行中」徽标、**停止实例**按钮，
以及统计卡里的运行计时、启动次数与**监听端口**。*

启动过程中：

- 卡片状态点会变成**运动中的进度环**（确定性进度，不是空转动画）；
- 启动完成后显示：**运行时长**、**本次运行计时**、**监听端口**；
- **Web 模板**的实例会被自动探测界面地址，卡片上直接出现 **打开界面** 按钮；
- 所有输出实时进入**右下角运行日志抽屉**（标题栏 `>_` 图标，或 `Ctrl+L`）。

### 关于端口：不用你操心

dsh 不传 `--port` 时硬编码落在 **3080**，所以同时启动多个 Web 实例会全抢同一个端口。
启动器的**自动端口避让**消除了这一点：

- 每个实例有**期望端口**（手写的 `--port` 或上次分配到的端口），被占用时在 **3080–3179** 内自动避让；
- 并发启动时靠进程内同步预留 + 操作系统绑定探测，**保证不会选中同一端口**；
- 整个区间占满时回落 `--port 0`，由内核分配 —— 端口耗尽也不会变成启动失败；
- 实际端口记录在**实例日志**、**界面（卡片统计项 / 详情页「监听端口」）**与**台账** `<root>/cache/ports.json` 三处；
- 非 Web 模板（headless / sdk / acp）**一个参数都不加**。

设计细节见 [自动端口分配设计说明](../design/port-allocation.md)。

## ④ 打开界面

Web 模板的实例启动后，点卡片上的 **打开界面**（或详情页右上角的同名按钮），
浏览器会打开自动探测到的地址，形如 `http://127.0.0.1:3080`。

到这一步，**你已经跑通了完整链路**。接下来：

- 想让这个实例具备更多能力 → [04 引擎与插件](04-engines-plugins.md)
- 想改实例的设置或看会话记录 → [05 设置·存档·日志](05-settings-saves-logs.md)
- 想再建几个实例并共享存档 → [03 实例管理](03-instances.md) → [06 隔离与共享](06-isolation-sharing.md)
