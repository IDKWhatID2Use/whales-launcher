# 03 · 实例管理

> 目标：把「一堆实例」管得清楚 —— 找得到、看得懂状态、改得动、删得干净、搬得走。

---

## 1. 列表页：一眼看清所有实例

![实例列表](../assets/tutorial/01-instance-list.png)

*图 1：实例列表页。（演示数据刻意覆盖了 6 种状态。）*

从上到下四层：

| 层 | 内容 |
|---|---|
| **页头** | 页面标题与说明，右侧是「刷新」与「新建实例」两个主操作 |
| **工具条** | 搜索框、状态筛选（全部 / 运行中 / 已停止 / **需处理**）、排序方式 |
| **卡片网格** | 每个实例一张卡：图标、名称、目录名、状态（含端口）、引擎版本与依赖数、最近启动、操作按钮 |
| **左侧实例栏** | 常驻的实例列表（顶部有「筛选实例」输入框），点一下直接进详情；**底部是「引擎版本管理」与「全局设置」入口**；主题切换在标题栏右上角的「主题」按钮 |

> 新 UI 没有旧版那排「概览统计」四宫格（实例总数 / 运行中 / 需处理 / 已装引擎版本）。
> 要看哪些实例需要介入，用工具条上的 **需处理** 筛选（见下）。

### 搜索

![搜索](../assets/tutorial/03-search.png)

*图 3：搜索框支持**实例名称、目录名、备注**三个字段。*

输入即过滤，右侧 `×` 清空。搜不到时的空态：

![搜索空态](../assets/tutorial/22-empty-search.png)

*图 22：没有匹配的实例时给出「清空筛选」按钮，而不是一片空白。*

### 筛选「需处理」

![筛选需处理](../assets/tutorial/02-filter-needs-attention.png)

*图 2：点工具条上的「需处理」，只看需要你介入的实例。*

**「需处理」是一个统一判定，不是一堆零散规则的拼凑** —— 筛选器与卡片徽标共用同一份判定，
所以不会出现「筛选里有、卡片上没有」的错位。以下情况都计入：

| 徽标 | 含义 |
|---|---|
| `目录缺失` | 实例目录不存在，可能已被移动或删除 |
| `引擎未安装` | 本地没有该实例绑定的引擎版本 |
| `记录异常` | `instance.json` 损坏 / 元数据被删 / 清单损坏 |
| `设置冲突` | 本地设置与共享设置不一致，尚未应用（详见 [06](06-isolation-sharing.md#共享设置冲突怎么处理)） |
| `已崩溃` | 上次启动异常退出（卡片上会有错误原因横幅） |

### 排序

四种方式：**最近启动 / 名称 / 创建时间 / 插件数**（工具条最右侧的「排序」下拉框）。

## 2. 读懂一张实例卡片

一张卡片上的信息都是「你接下来会想知道的」：

```
┌────────────────────────────────────────────┐
│ 🐳  我的工作台                 ● 运行中 :3080 │  ← 图标 + 名称 + 状态（含端口）
│     workbench                               │  ← 目录名
│                                             │
│ 引擎 0.1.6-alpha.2 · 0 个依赖 · 3 分钟前      │  ← 引擎版本 / 依赖数 / 最近启动
│                                             │
│ [■ 停止] [🌐 打开界面]         [详情] [更多 ▾] │  ← 主操作 + 详情 + 更多
└────────────────────────────────────────────┘
```

- **状态**：`●` 圆点 + 文字两个通道同时表达（已停止 / 运行中 / 已崩溃…），
  异常实例的圆点是红色，正常静止态是灰色，运行中是绿色；
- **端口**（`:3080`）：运行中的 Web 实例直接把端口跟在状态后面，悬停可看完整界面地址；
- **异常时**卡片上会直接出现黄色原因条（引擎未安装 / 目录缺失 / 记录异常…），不用点进去猜；
- 卡片按钮是 **启动（运行中变「停止」）**、**详情**、**更多**；
  运行中的 Web 实例会多出一个 **打开界面** 按钮。

## 3. 卡片「更多操作」

![卡片更多操作](../assets/tutorial/05-card-more-menu.png)

*图 5：卡片右下角「更多」打开的菜单。*

| 菜单项 | 作用 |
|---|---|
| 启动 / 停止 | 与卡片主按钮等价 |
| 打开界面 | 运行中的 Web 实例：在浏览器里打开探测到的地址 |
| 打开文件夹 ▸ | 子菜单五选：**根目录 / 主目录 home / 工作区 workspace / 日志 logs / 插件 plugins** |
| 实例详情 | 进入详情页的「插件」页签 |
| 编辑设置 | 进入详情页的「设置」页签（实例信息也在那里改，见下一节） |
| 刷新状态 | 只重新读取该实例的运行时状态 |
| 删除实例… | 二次确认后删除（**红色**，运行中时直接提示先停止） |

> 运行中的实例不允许删除 —— 先停止再删。

## 4. 编辑实例信息

![编辑实例信息](../assets/tutorial/19-edit-instance.png)

*图 19：编辑实例信息的位置是 **详情页 →「设置」页签 →「实例信息」折叠段**（卡片 `⋯` 菜单里的「编辑设置」就是直接跳到那里）。*

可以改**实例名称、图标、强调色、备注**（引擎版本这一项只读）。两个要点：

- 这里只改**启动器侧的展示信息**，不影响 profile 与插件；
- **目录名保持稳定，不随重命名变化** —— 重命名不会搬动磁盘上的目录，
  所以共享链接、外部脚本里的路径都不会因为改名而失效。

> 旧版是一个独立的「编辑实例信息」模态框；新 UI 把它并进了详情页的设置页签，
> 与 `settings.yaml`、隔离策略、启动参数放在同一页，改完点该段的保存按钮即可。

## 5. 删除实例

![删除确认](../assets/tutorial/20-delete-confirm.png)

*图 20：删除确认。新 UI 的确认框**没有**「同时删除磁盘上的实例目录」勾选框 ——
它明确写着：只把实例移出列表，磁盘上的实例目录原样保留。*

删除确认框里写得很清楚：

| 结果 | 说明 |
|---|---|
| 实例列表记录 | 从启动器中移除，**不可撤销** |
| 磁盘上的实例目录 | **保留**（含 `home / workspace / 日志`），需要时可在文件管理器中自行清理 |

> **共享目录不受影响。** 若该实例的工作区/存档链接到了 `shared/`，删除实例**不会**清理共享区
> —— 这是 core 的有意设计（避免误删别的实例正在用的数据），只报告孤儿目录，需要你手工处理。
> 详见 [06 隔离与共享](06-isolation-sharing.md#删除实例时共享区会怎样)。

「全局设置 → 危险操作 → 删除实例前二次确认」控制这个确认框是否弹出。

## 6. 实例包：导出与导入

实例包（zip）是把一个实例**搬到另一台机器**的载体。

> ⚠️ **当前 WinUI 3 版本尚未在界面上提供这两个入口。**
> 后端通道与文件选择器都已就绪（`pack:export` / `pack:import` / `host:pickPackFile`），
> 但还没有任何页面调用它们 —— 旧 Electron 版列表页右上角的「从实例包导入」按钮、
> 卡片 `⋯` 菜单里的「导出实例包」在重构后**都不存在**。
> 因此本节配图仍是旧的 Electron 界面截图（见
> [CORRESPONDENCE.md](../assets/tutorial/CORRESPONDENCE.md) 第 6 节），
> 下面的流程描述的是**后端语义**，等入口落地后再按新界面补图。

### 导出

（界面入口待补）导出实例包 → 选择保存位置。导出完成后会弹提示，并可**一键复制路径**。

包内结构（**不含 `node_modules`**）：

```
whalelauncher-pack.json              包元数据 + 实例元数据 + 依赖清单
home/profiles/<profile>/package.json profile 清单（组合包列表 + 依赖）
home/profiles/<profile>/cordis.patch.yml  用户 patch 层
home/settings.yaml                   实例设置（有内容才带）
README.md                            包说明
```

**为什么不打包 `node_modules`**：与 PCL2 整合包同样的取舍 —— 依赖按清单在导入端重装，
包体小得多，也不会把平台相关二进制带错。

### 导入

![从实例包导入](../assets/tutorial/21-import-pack.png)

*图 21（**旧 Electron 界面**，新 UI 尚无此入口）：列表页右上角「从实例包导入」。*

导入时会：

1. 校验包元数据与版本；解压**手工逐条写入并校验路径**（拒绝绝对路径与 `..`），避免 zip-slip 把文件写到目标目录之外；
2. 按 manifest 重装依赖；
3. 完成后弹出提示，可直接 **查看实例**；有告警时（例如引擎版本未安装）会一并列出。

> 导入后若提示「引擎未安装」，去 [引擎版本管理](04-engines-plugins.md) 装上对应版本即可启动。

## 7. 目录：实例到底存在哪

```
instances/<实例名>/
├── instance.json       # 启动器元数据（唯一事实源）
├── home/               # ← 该实例专属的 DSH_HOME
│   ├── profiles/<profile>/    # package.json（插件与组合包）+ cordis.patch.yml
│   ├── settings.yaml          # 该实例独享的设置
│   ├── .credentials.yaml      # 凭证（可继承主 home）
│   └── sessions/              # 该实例的会话
├── workspace/          # 默认工作文件夹（可为 junction）
└── logs/               # 启动日志
```

启动实例时，启动器以 `DSH_HOME=<实例>/home`、`cwd=<实例工作区>` 派生 dsh 进程 ——
所以删掉整个实例目录就等于彻底删除，不会留残留、也不影响别的实例。
