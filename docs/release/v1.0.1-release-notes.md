# WhalesLauncher v1.0.1 —— WinUI 3 原生版

DeepSeek Harness (dsh) 的实例与版本管理启动器。本次是**前端整体替换式重构**后的首个发布：
旧 Electron + DOM/CSS 前端已全部废弃，改为 **WinUI 3（C#/XAML）+ Windows App SDK** 原生界面。

## 下载

| 文件 | 说明 |
|---|---|
| `WhalesLauncher-v1.0.1-win-x64.zip` | **完整应用**（231.5 MB，解压即用） |

解压后双击包内的 `WhalesLauncher.exe` 即可运行。**不需要安装 .NET 运行时**（已自包含）。

## 环境要求

- **Windows 10 1809（10.0.17763）或更高，64 位**
- **Node.js 22+** —— 必须自行安装，见下

## 重要：需要自备 Node.js

WhalesLauncher 是启动器，界面本身不需要 Node；但要**管理 dsh 实例**就必须有一个真正的
Node.js：<https://nodejs.org/>

程序会按 `$WHALES_NODE_PATH` → 配置里的 `nodePath` → 系统 `PATH` → 常见安装位置的顺序
探测，每个候选都**实际执行一次探针**验证，绝不按路径名猜测。没探到时界面仍可打开，并在
「全局设置 → Node 运行时」里提供手动指定入口。

> ⚠️ 不要用非官方 Node 运行时（例如某些软件内置的 Node）去跑 dsh：dsh 的原生模块按运行时
> 指纹白名单匹配，非官方指纹会直接启动失败（`node-addon-require-builtin unsupported`）。

## 这个版本做了什么

**界面（全部重写）**

- **WinUI 3 原生**：控件与视觉令牌全部取自
  [microsoft-ui-xaml](https://github.com/microsoft/microsoft-ui-xaml) 官方体系，颜色/字号/圆角
  一律走内置 `ThemeResource`，不自建色板、不硬编码色值
- **原生窗口**：官方 `TitleBar` 并入客户区，窗口按钮由系统绘制（保留 hover / Snap Layouts）
- **Mica 窗口底面**，系统不支持时自动退回实色兜底层
- **深浅双主题**；注意当前契约里 `theme` 只有 `dark`/`light`，界面上**明确写着"不跟随系统"**
  —— 这是如实呈现的契约缺口，不是漏做
- **8 个页面**：实例列表、实例详情（插件 / 设置 / 存档 / 日志）、引擎版本管理、创建向导（4 步）、全局设置
- 日志渲染有**行数上限 + 增量渲染**，洪峰下不卡死 UI

**架构**

- C# 前端 ↔ **Node 侧车进程**（`dist/bridge/server.cjs`），NDJSON over stdio，协议 v1
- 原 TypeScript 业务引擎（`src/core`，约 7 000 行）**一行未改**直接复用
- 契约唯一事实源 `src/shared/contracts.ts`；启动时 `__handshake` 机械对账 39 条通道

**质量**

- 桥接冒烟 **141/141** 通过；core 单元测试 **17/17** 通过
- **渲染层 UI 自动化测试**：9 个界面单元、**69 条断言 → 68 通过 / 0 失败 / 1 不可判定**
- 构建期断言：`src/main/**` 引用数 = 0（旧前端不可回流）

## 发布后修正（本仓库内已修复，尚未随新的发布包重新分发）

下方「已知问题」里有三条已经修掉了。**已下载的 `WhalesLauncher-v1.0.1-win-x64.zip`
仍然包含这三条缺陷** —— 校验值不变，请以本节的说明为准；下一个发布包会带上修复。

| 原「已知问题」 | 现状 | 修法与验证 |
|---|---|---|
| 实例包导入/导出暂无界面入口 | **已修复** | 实例列表页页头新增「**导入实例包**」按钮；卡片「更多」菜单在「刷新状态」与「删除实例…」之间新增「**导出实例包…**」。两者都走既有通道（`pack:import` / `pack:export`），导入/导出期间互相禁用、页头显示进度条；导入完成会刷新列表并按告警等级提示（例如引擎版本未自动回退）。超时从默认 30 秒放宽到 30 分钟（导入要按清单重装依赖）。教程配图已按新界面重拍 |
| 卡片「更多」菜单在自动化调用（UIA Invoke）时会触发 `COMException` | **已修复** | 卡片的「更多」从 `DropDownButton` 换成「普通 `Button` + `Button.Flyout`」（与插件页早已在用的形态一致）：`InvokePattern` 与鼠标点击从此汇到同一个 `Click`，不再依赖 `DropDownButton` 的展开状态机。UI 自动化用例 P1-06 用 `InvokePattern.Invoke` 打开菜单并核对全部 8 个菜单项；教程截图 05 / 19 / 20 / 24 四枪也改用 `invoke` 打开菜单，连跑两次没有再产生 `crash.txt` |
| 崩溃后的实例卡片状态需要手动点「刷新」 | **已修复** | 根因是 C# 状态层没有订阅后端**早就在推**的 `log:state`（core 退出链会推最后一帧 `crashed`），兜底轮询又用「最近 2 分钟内崩过」这种时间窗口判据，窗口外就停表。现在：① `AppState` 订阅 `CoreBridge.LogStateChanged`，把推送汇入 UI 线程后就地更新该实例的运行时状态；② 轮询判据改为「状态是否还可能变」（`running`/过渡态/崩溃但 PID 未回收），进入终态立刻停表。用一个「启动即崩」的合成引擎跑真实启动流程、全程不点刷新：卡片 4 秒内自行变为「已崩溃」，主按钮同步变为「重新启动」 |
