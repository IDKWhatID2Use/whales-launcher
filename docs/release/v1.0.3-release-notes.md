# WhalesLauncher v1.0.3 —— 修实例启动崩溃、设置页勾选与崩溃页排版，并修正打包

DeepSeek Harness (dsh) 的实例与版本管理启动器。本版修掉三个**用户直接反馈**的缺陷，
并修掉**发布流程本身**的一个缺陷：此前两版的发行包里，编译进侧车（bridge）的版本号都是
**上一版**的（v1.0.2 的包内写着 1.0.1，v1.0.1 的包内写着 1.0.0），于是「关于」页显示的
「启动器版本」与实例包元数据里的 `launcherVersion` 都写错了版本。

## 下载

| 文件 | 说明 |
|---|---|
| `WhalesLauncher-v1.0.3-win-x64.zip` | **完整应用**（解压后 231.71 MB；zip 89.32 MB，解压即用） |

解压后双击包内的 `WhalesLauncher.exe` 即可运行（包内另有 `README-发布说明.txt` 与
`启动 WhalesLauncher.bat`）。**不需要安装 .NET 运行时**（已自包含）。

## 环境要求

- **Windows 10 1809（10.0.17763）或更高，64 位**
- **Node.js 不需要你预装** —— 本机已有的会被优先沿用；一个都没有时，启动器会**自动下载
  官方 Node v22 LTS 便携版**（约 30MB，校验官方 SHA-256，解压到 `<启动器根>\runtime\node\`，
  免管理员权限、不改系统设置，且自带 npm）

## 本次修正（相对 v1.0.2）

### 1. 实例启动崩溃：`settings.yaml` 的换行被写成纯 CR（用户报告 krea2 启动即崩）

- **现象**：实例每次启动都崩，日志尾部是
  `settings-file: invalid document … BLOCK_AS_IMPLICIT_KEY at line 1, column 15…`。
- **根因**：WinUI 的 `TextBox`（RichEdit）用 `\r` 作段落分隔符。在「实例详情 → 设置」里编辑并
  保存 `settings.yaml` 时，读进来是 CRLF、交回后端的是**纯 CR** 文本；原来后端只做
  "YAML 能解析"校验，而校验用的 js-yaml **接受**纯 CR，dsh 用的 `yaml` 包**不接受** ——
  整份文件被当成一行，实例启动必然失败。前一个版本写入的文件因此是坏的。
- **修法（三层）**：
  1. 编辑器读写一律归一到 `\n`（[`YamlEditorView.xaml.cs`](../desktop/src/WhalesLauncher.App/Views/Detail/YamlEditorView.xaml.cs)）——
     顺带修掉两个同源症状：装载完成就误报"有未保存的更改"、行号列只数出 1 行；
  2. 后端写入前归一，并让 `validateYaml` **显式拒绝**孤立 CR
     （[`src/core/profile.ts`](../src/core/profile.ts)）；
  3. 实例包导入时同样归一（[`src/core/modpack.ts`](../src/core/modpack.ts)）。
- **回归护栏**：新增真 dsh 端到端用例"编辑器式 CR 文本经归一后实例必须能启动"，以及
  CR/CRLF 归一与孤立 CR 拒绝的单元用例。

### 2. 实例设置页看不到当前隔离策略（用户报告）

- **现象**：四个维度（工作区 / 存档 / 设置 / 凭证）八个选项**全是未选中的空圆点**，
  用户无法判断当前实例用的是哪一档；只有 `AutomationProperties.Name` 里写着维度名（喂屏幕阅读器）。
- **根因**：`muxc:RadioButtons` 的**程序化勾选不生效** —— `SelectedIndex` / `SelectedItem`
  写进去读回都正确，界面就是不画勾。
- **修法**：四个维度改用普通 `RadioButton` + `GroupName`（契约字面值放 `Tag`，选中态直接写
  `IsChecked`），并补上**屏幕上可见的分组小标题**（工作区 / 存档 / 设置 / 凭证）。
- **验证**：UI 自动化用例 P3 全 8 项通过（含新增 P3-08「每个维度都有可见分组标题」），
  截图确认当前档位已被勾中。

### 3. 崩溃页：日志读不到、按钮被顶歪（用户报告）

- **现象**：实例崩溃后，崩溃原因与 stderr 原文被塞进页头那一行说明里；页头被撑成十几行，
  右列的「返回 / 打开文件夹 / 启动」按钮随之错位，而被挤扁的内容区**无法滚动**。
- **修法**：页头只留"状态 · 端口 · 地址"，崩溃原文改为页头下方**限高 160 且可滚动**的错误条
  （等宽字体、可选中复制），并给一个「查看日志」按钮直接跳到日志页签；实例卡片上的崩溃摘要
  截断到 120 字（全文进 ToolTip），不再把卡片撑高。

### 4. 发布流程：包内版本号是上一版的（v1.0.1 与 v1.0.2 均受影响）

- **根因**：版本号在**构建期**编译进 `dist/bridge/server.cjs`（`--define:__WHALES_APP_VERSION__`），
  而 `dist/` 不入库；`desktop/publish-release.ps1` 此前只做 .NET Release 构建、**不重建侧车**，
  于是磁盘上陈旧的 bundle 静默进包。后果：`app:version`（「关于」页的「启动器版本」）
  与 `pack:export` 写进实例包的 `launcherVersion` 都是错的版本号。
- **修法**：`publish-release.ps1` 现在**先重建侧车**，并对 `dist/bridge/server.cjs`
  与**入包后**的 `bridge/server.cjs` 各做一次**版本断言**：与 `package.json` 不一致就退出
  （exit 4 / 2），不再把版本号错的包发出去。
- **验证**：本次发布的包解压后实跑，应用「关于」页显示 **启动器版本 1.0.3**。

## 已知问题（如实列出）

- **日志页只显示实例运行时的实时输出**，没有磁盘回填：崩溃后打开「日志」页仍是空态。
  崩溃原因因此固定在崩溃条里呈现（可滚动、可复制），而不是只放在日志页。
- **深链进入详情页的页签选择存在偶发竞态**：全套 UI 用例首轮偶见「日志」页 6 项失败
  （选中页签仍是「插件」），单跑与复跑均通过。已登记，未在本版修。
- **教程配图未随本版重拍**：`docs/assets/tutorial/*.png` 里画的左栏仍是改造前的形态，
  设置页的隔离选项也还是"未勾中"的旧截图。
- 高对比度主题与 150% 文本缩放**未走查**（延续 v1.0.1 的登记）。
- 声明式 `SelectedIndex` 在 `muxc:RadioButtons` 上的具体触发条件未继续深挖：本版只把
  实例设置页换成普通 `RadioButton`，向导页第 4 步（XAML 里内联选项）一直是正常的。
